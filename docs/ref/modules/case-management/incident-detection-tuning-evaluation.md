# Detection tuning replay evaluation

A separate incident workspace page evaluates operator-supplied, externally executed paired baseline/candidate detection results. It is browser-local, deterministic and makes no provider, server or rule changes. It accepts only distinct version tokens, a declared holdout split and up to 5,000 uniquely identified paired samples with independently supplied malicious/benign/unknown labels and strict boolean outcomes. It cannot verify the authenticity of labels, that the holdout is independent, or that the named rule versions actually generated the outcomes. No arbitrary query, logs or detection rule DSL is accepted.

Confusion matrices, recall, false-positive rate and benign alert reduction are reported with explicit denominators; unknown labels are excluded from confusion matrices and reported separately, undefined ratios are null. The conservative review gate blocks any previously detected malicious sample being missed, any new benign alert, unknown labels, fewer than ten examples in either class, or no demonstrated benign alert reduction. A net recall gain cannot hide an individual lost malicious detection. The minimum sample size is a review floor, not a confidence claim. Passing means eligible for human review only.

The evaluator does not perform historical replay, estimate production-wide noise reduction, approve a rule, or change any configuration.
