# Experimental incident AI assessment

The dedicated dashboard assessment route is absent by default. Configure server-only `wazuh_ai_assistant.incidentAssessment` with providerId, exact baseUrl, exact model and allowedTlp (defaults to TLP:CLEAR). Only an existing OpenAI-compatible provider matching all three configured values is accepted; no user-selected URL or model, no provider discovery or fallback, no separate model runtime. The existing adapter, credential cipher and fetch-time URL guard are reused. TLP:RED and TLP:AMBER+STRICT are never accepted. TLP:GREEN/AMBER require explicit operator disclosure authorization; do not downgrade a label merely to obtain an assessment. Configure egress and trusted provider handling independently; a local endpoint name does not establish privacy.

The route requires explicit request consent, existing caller incident and provider permissions, exact incident UUID/revision and original-caller finding visibility. It reads only the first five linked finding positions; missing, hidden and uninspected counts are distinct. The provider receives bounded structured facts only: lifecycle enums, counts, assignment presence, ATT&CK-shaped IDs (not a validated ATT&CK catalog), entity kinds and timestamp presence. No incident UUID, title, description, user/host/IP values, raw timestamps, source references, notes, commands, arbitrary model prompt, tool or history are passed. This is data minimization, not anonymization or a guarantee that aggregate facts are nonsensitive. Coverage does not imply every field or finding is available. No external disclosure before successful preflight; a race after the final preflight cannot be atomically prevented and must be considered in deployment policy. The provider sees no executable tools and the route does not run chat orchestration.

Model output must be strict JSON containing up to five distinct fixed human-review action IDs with known evidence references. There is no free-text generated incident narrative, classification, severity override or response action. A valid reference is not proof of semantic support. The result is advisory only, shown with exact fact references and incident revision; no conversation persistence or incident writes. Invalid/partial output, reasoning fallback, stale revision and provider errors fail closed. One assessment per dashboard process, 60-second abort signal and 4,096-character output cap; actual provider cancellation and multi-instance load require local qualification. Existing adapter retries and reasoning token usage are not a hard inference token cap. The original provider SSRF guard has its documented DNS/redirect limitations; enforce network egress at deployment.

Local validation: enable on disposable stack only; assert outgoing payload contains no identifiers or free-text, no tools, no conversation or mutation; test provider mismatch, label policy, denied finding/incident/provider access, stale revision, empty and partial pages, malformed output, interruption, concurrency and small-model JSON compliance. No claims of clinical or forensic certainty.

## AI Review and Agentic SOC

The request explicitly selects ai_review or agentic_soc. Review uses one model pass on up to five linked positions. Agentic SOC requires additional server opt-in agenticEnabled (false by default) and uses two model passes: a strict model-selected probe plan, then a final assessment. It may inspect five additional linked positions and/or query one exact Wazuh rule ID from the first visible page over the preceding 24 hours. The fixed count-only search runs as the caller against wazuh-findings-v5*, with partial results disabled, 10-second search timeout and a 10,000 hit tracking cap (lower bound explicitly identified). No raw rule ID or results beyond counts leave the dashboard. The exact wazuh.rule.id projection is separate from the display fallback. No arbitrary tool or DSL is accepted. Invalid or unavailable selected probes fail the assessment rather than fabricate results. Each provider call rechecks current revision and disclosure policy.

Agentic output includes a cited classification hypothesis (insufficient evidence, possible true positive, benign positive or false positive) and up to three cited tuning review categories. Hypotheses are unconfirmed; frequency does not establish benignity. Tuning proposals require positive/negative replay, detection coverage and analyst approval. No rule changes, classification, suppression, closure, response dispatch or persistent agent session. The 120-second abort signal is a best-effort bound, not a CPU/token guarantee. Additional rule prevalence may reveal aggregate fleet-level information to the configured provider: explicitly authorize this before enabling Agentic SOC.

## Optional private assessment copy

Every successful assessment has server-minted UUID, time, configured model/provider identity, schema version and SHA-256 of the exact structured digest. These are informational provenance, not signatures. Separately enable privateReportSavingEnabled (default false) and opt in per run. The dashboard checks a real user identity and incident revision/disclosure policy, then uses the existing current-user sessions creation API. The saved copy is a normal editable/deletable AI Assistant conversation subject to its existing retention (RC2 default seven days), not immutable incident evidence. No shared case write, no automatic retry after an ambiguous save, no raw source, no API key or URL. Privacy replay flag is false; do not resume the saved copy with an unapproved provider, especially with privacy off. Saving requires the existing session-create permission and correct DLS; later access to this private copy follows session permissions, not dynamic incident access. Do not enable saving if this retention/access behavior is unacceptable. Durable incident-owned reports with independent ACL and retention remain outstanding.
