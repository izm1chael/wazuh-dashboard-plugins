# Bounded detection outcome history

A user selects a canonical, single-scalar wazuh.rule.uuid visible in the first 25 linked finding positions of the current incident. The dashboard rechecks the exact incident revision and source visibility before comparing at most ten other currently closed incidents ordered by last update, using the original caller's ordinary incident and finding read actions. At most five linked positions per sampled incident, one process-wide concurrent scan and a 30-second between-request deadline. This is a sampled current-state comparison, not an exhaustive, point-in-time or rule-version history. Query failures abort rather than silently omit cases. Caller visibility, retention, missing identities, uninspected links, current classification and non-atomic multi-request observation are explicit limitations. Each matched incident is counted once; partial and uncertain nonmatches are distinct. No source values or historical incident IDs returned, no provider call, no write. Classifications are incident-level, not finding ground truth or a rule false-positive rate. No display-ID or generic rule.uuid fallback. Live permission, data shapes, load and UI require qualification.
